1. How the portal is built

The portal runs on Cloudflare, served from a global network so it loads fast from anywhere and stays up. The pages are standard web pages. The working parts (login, data, uploads, schedule, daily reports) run as small on-demand functions rather than one always-on server, which keeps it fast and low maintenance. Every visitor passes through a security gate that checks who they are before any page loads, and each person's role controls what they can see. The interactive tools (Design Studio, HR) sit inside the portal behind that one login.

2. Where the data lives, and how it is backed up

There are two layers, by design:

Source of truthThe team's existing SharePoint / Microsoft 365 Excel workbooks (Bid Log, Project Master, BD Master, the Budget and Estimate template, Insurance). These are the master files the partners already maintain. Nothing changes about how you keep them.
What the portal showsA set of generated data files rebuilt every night from those workbooks. This morning's refresh carried 174 bids, 22 projects, and 160 business-development records.
BackupsMicrosoft 365 version-histories and backs up the master workbooks automatically. The login database is dumped to a weekly backup. And the entire platform lives in version control, so every page and every data file is recoverable to any prior point.

Important habit: data edits belong in the SharePoint master files, not typed into the portal, because the nightly refresh rebuilds the portal's copy from the masters.

3. The URL, and the GoDaddy question

Recommendation

Yes to a professional URL. Point a subdomain of the company's own domain, such as portal.pierfoundations.com, at the portal with a quick DNS change. Keep the hosting on Cloudflare. Use GoDaddy only as a registrar if you like, not as the host.

Why not host on GoDaddy: a domain (the URL) and hosting (where the app runs) are two different things. GoDaddy is fine for holding a domain, but its web hosting cannot run the parts that make this portal work, the login functions, the per-user database, and the security gate. Moving the hosting there would mean rebuilding the backend for no gain, and we would lose the instant rollback and zero-downtime updates. Pointing your own subdomain at Cloudflare gives you the polished company address and keeps the strong foundation underneath.

4. Can we go live now and edit as we go?

Yes. Updates publish all at once with no downtime, and Cloudflare keeps every previous version for instant rollback if an update ever misbehaves. Layout edits touch only the pages, never the data. Editing while people are logged in is fine, their sessions carry through. We have already added features in production this way.

5. How updates ship once live

Updates go out through a single controlled step that publishes the new version, verifies the security gate held, and records the change. Because every prior version is retained, any update can be rolled back in seconds. In short, we can improve layout and features continuously, safely, without taking the portal offline.

Bottom line: the platform is built to go live now and evolve as we go.
