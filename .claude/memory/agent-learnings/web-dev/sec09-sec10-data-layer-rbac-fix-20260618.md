# SEC-09 / SEC-10 — Data-Layer RBAC Fix (PF Platform)

## The Vulnerability (from security-auditor re-audit)
Page-level RBAC (areaForPath gating *.html) was correct, but the sensitive
pages are CLIENT-SIDE SHELLS that `<script src="/data/xxx.js">` their payload.
`areaForPath()` blanket-allowed the whole `/data/` prefix as 'general', so a
field_ops user just GET `/data/bid-log.json` directly (200) and read every
financial/contract value. Gating the .html did nothing. The old test suite
even asserted `/data/` was ALLOWED — baking the hole in as "correct".

## SEC-09 Fix (functions/lib/auth.js)
1. REMOVED `/data/` from STATIC_ASSET_PREFIXES.
2. Removed `.js`/`.mjs`/`.json` from STATIC_ASSET_EXT_RE (so /data/*.{js,json}
   can't fall through to 'general' by extension). Real shared scripts live under
   /js/ /vendor/ /assets/ /design-studio/ (still prefix-allow-listed).
3. Added `DATA_FILE_AREAS` map classifying EVERY /data/ file by CONTENT.
4. areaForPath() now routes `/data/` BEFORE static checks: explicit map ->
   SENSITIVE_NAME_RE heuristic -> DEFAULT-DENY (user_admin). Fail closed.

## Classification (file -> area -> field_ops?)
SENSITIVE (admin/partner only): bid-log.json, live-data.js, pricing-data.js,
budget-actual-poet.js, project-records.js, project-record-poet.js,
projects-data.js (revenue/AR), estimate-template.json, project-history.js,

FIELD-SAFE (field_ops ok, NO $): production-data.js, progress-data.js,
timesheets.js (hours/cost-CODE labels/per-diem night COUNTS — verified no
wages/rates/dollar amounts), schedule-seed.js, schedule-seed-state.json,
schedule-data.js, fo-projects-field.js (new derivative).

## The mixed-sensitivity trap (key learning)
awarded-projects.js + project-record-poet.js contain BOTH the field crew's
needed project names/scope AND contract $ values. The fo-projects FIELD view
(field_ops landing) reads name/city/discipline/columns/LF — but the file also
has `value: 326200`. Gating the whole file breaks the field view; not gating it
leaks $. Solution: a FIELD-SAFE DERIVATIVE `data/fo-projects-field.js`
(window.PF_FO_PROJECTS) generated by stripping all $/GC/contract fields. Loaded
only for field_ops; renderList() prefers it, admin/partner fall back to
PF_AWARDED. NOTE: this is a static strip of current data — the sync pipeline
(build-awarded-index.py) must regenerate it (build-fo-projects-field.py TODO)
whenever sources change.

## field_ops UI (so gating doesn't 403-noise the crew)
- Added `functions/api/me.js` -> {name, role} from context.data.session (works
  for shared-auth admin too). Classified /api/me -> 'general'. Fails closed 401.
- index.html: a SYNC XHR to /api/me at the top of <body> decides which feeds to
  document.write (in order, before modules). field_ops gets ONLY field-safe
  feeds + fo-projects-field.js; admin/partner unchanged (all 8 sensitive feeds).
  Fail closed: any /api/me error -> role stays field_ops (least privilege).
- CSS body.role-field-ops hides non-field-safe nav sections (data-fo-safe /
  data-fo-mixed / data-fo-hide attributes). Role-UI init runs LAST, prunes
  mobile tabs + FAB, lands field_ops on fo-projects (not the financial dash).
